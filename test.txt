3. 화면은 있지만 데이터가 예시인 것
====================================================================
- 주변 장소(지도): 화면 완성, 데이터는 예시. DB places 에 실제 데이터를 채우면 됨
- 쓰레기 배출 요일: 화면 있음, 데이터는 상수. trash_schedules 에 채우면 됨
- 알림: 일부가 하드코딩된 예시. notifications 표가 실제로 채워지게 서버가 만들어야 함


4. 정리
====================================================================
- 우리 프로그램의 약속(운영 정책)과 직접 어긋나는 것은 "신고(제3조)"와 "단계별 제재(제7조)".
- 장소 후기, 대댓글, 홈 꿀팁 선정은 확장 기능이라 안 만들어도 됨.
- reports 표는 만들어져 있지만 쓰는 코드가 없는 "예약된 표".
  신고 중복 방지 / 신고 횟수 집계는 reports 에 UNIQUE 키 하나(reporter_id, target_type, target_id)만 추가하면
  새 표 없이 가능. 횟수는 COUNT 로 집계.
- 신고 기능을 넣기로 하면: 화면(신고 버튼, 관리자 신고 탭) + API + UNIQUE 키 1개.
  안 넣기로 하면: 운영 정책 제3조 문구를 고쳐서 기능과 맞추기.
