규모 감각
--------------------------------------------------------------------
화면이 이미 있어서 API 약속이 backend/openapi.yaml 에 주소 81개 · API 115개로 정리돼 있다.
1단계만 만들어도 로그인 화면이 바로 실제 서버와 연결된다.
그다음은 3단계(일정, 월세, 가계부)가 홈 화면의 핵심이라 효과가 가장 크다.


0단계. 바탕 작업
====================================================================
[ ] Spring 프로젝트 생성 (Java 21, Gradle 확정 - Maven 은 쓰지 않음), 포트 8080, 주소는 모두 /api 로 시작
      (IntelliJ: backend 폴더 자체를 프로젝트로 열고 Load Gradle Project)
[ ] backend/openapi.yaml 을 Swagger 에 Import 해 검토, 서버가 생기면 springdoc 명세와 비교
[ ] MySQL 연결, db/schema.sql 적용 (Docker Compose 추천)
[ ] JWT 로그인 검사 (Authorization: Bearer <accessToken>)
[ ] 오류 응답 형식 통일: { "message": "..." }
[ ] 401(토큰 없음/만료), 403(권한 없음), 404(남의 데이터) 규칙
[ ] CORS 설정, DATETIME UTC 저장 기준·ISO 응답·한국 달력 날짜 계산 구분
[ ] "내 데이터만 접근" 규칙
[ ] DB id(BIGINT)를 JSON 에서 문자열로 내려주기
[ ] 서버 비밀 키는 환경변수/비밀 저장소로 관리 (깃에 올리지 않기)


1단계. 회원가입 / 로그인 (프론트에 호출 코드가 이미 있음)
====================================================================
[ ] 회원가입: 입력 검사(아이디, 비밀번호, 닉네임), 중복 방지, 비밀번호 해시, 약관 동의 기록
[ ] 로그인: 아이디 또는 이메일, 로그인 유지, 정지 계정 차단, 마지막 로그인 시각 기록
[ ] 내 정보 조회/수정: 닉네임, 소셜 첫 가입 시 주소와 약관 동의
[ ] 로그아웃
[ ] (선택) 토큰 재발급 POST /api/auth/refresh - 재발급 토큰은 httpOnly 쿠키
[ ] 비밀번호 변경
[ ] 회원 탈퇴: 개인 데이터 정리, banned_identities 차단 HMAC 유지
[ ] 첫 로그인 판단: 서버가 firstLogin 값을 내려줘서 설문 화면으로 보내기
