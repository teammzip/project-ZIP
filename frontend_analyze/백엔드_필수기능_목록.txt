====================================================================
작성일: 2026-11-01
근거: frontend/API.md, db/schema.sql, 프론트 코드(frontend/src)
함께 볼 문서: 백엔드_연동_가이드.txt (화면별 상세), 외부API_정리.txt (외부 서비스)

사용법
--------------------------------------------------------------------
- 앞의 [ ] 를 만든 기능은 [x] 로 바꿔 가며 진행 상황을 본다.
- 등급
    A = 필수 : 이게 없으면 앱이 서버로 동작하지 않는다 (MVP)
    B = 중요 : 서비스 품질에 필요. A 다음에 만든다
    C = 나중 : 있으면 좋음. 시간이 남을 때
- (연결됨) = 프론트에 호출 코드가 이미 있어서 서버만 만들면 바로 붙는다.
- 번호 N번 = frontend/API.md 의 해당 번호


0. 바탕 작업 (모든 기능의 전제)  [A]
====================================================================
[ ] A 서버 프로젝트 만들기 (Spring Boot 등), 포트 8080, 주소는 모두 /api 로 시작
[ ] A DB 연결 (MySQL 8) + db/schema.sql 적용, 마이그레이션 관리 (Flyway 등)
[ ] A JWT 로그인 처리: 요청 헤더 Authorization: Bearer <accessToken> 검사
[ ] A 오류 응답 통일: { "message": "..." } (이 문장이 화면에 그대로 보임)
[ ] A 401(토큰 없음/만료), 403(권한 없음), 404(남의 데이터) 규칙
[ ] A "내 데이터만" 접근: 일정/가계부 등은 토큰의 사용자 것만 조회/수정
[ ] A JSON 규칙: 키는 camelCase, id 는 문자열, 날짜 'YYYY-MM-DD', 금액 원 단위 정수
[ ] A CORS / 개발용 프록시 (프론트 localhost:3000 -> 백엔드 localhost:8080)
[ ] A 비밀 키는 서버 .env 에만 (깃에 올리지 않음)
[ ] B 목록 응답 규칙: ?page=0&size=20 -> { items: [...], hasNext: true }
[ ] B 파일 업로드 저장소 (로컬 폴더 -> 나중에 R2/S3)
[ ] C 요청 제한(Rate limit), 로그, 오류 감시(Sentry)

[ ] A 입력 검사: 아이디 6~16자 영소문자+숫자 / 비번 8~16자 영문+숫자+특수 / 닉네임 2~12자

[ ] A 비밀번호는 해시로 저장 (평문 금지)
[ ] A user 응답에 판단값 포함: firstLogin, agreedAt, role, status, region

[ ] A 정지된 계정 로그인 차단 (403 + 사유/해제 시각 메시지)

[ ] B POST   /api/auth/phone/send            휴대폰 인증번호 발송 (연결됨)

13-1. 결정이 필요한 작은 기능 (API 약속이 없음)
====================================================================
[ ] B 설정 > "데이터 초기화"
      지금은 이 기기에 저장된 기록(일정, 가계부, 메모, 커뮤니티, AI 대화, 지도 설정, 프로필, 대출)을
      처음 상태로 되돌린다. 서버가 생기면 "서버에 있는 내 기록도 지울지"를 정해야 한다.
        방법 1) 서버 기록도 삭제: DELETE /api/me/data 같은 API 필요 (계정과 로그인 정보는 유지)
        방법 2) 기기 저장분만 초기화: 서버 API 불필요 (서버 기록은 그대로 남음)
      -> 어느 쪽인지 팀에서 정해야 함. 정지/경고 기록은 어느 쪽이든 지우면 안 됨 (정지 우회 방지)
[ ] B 회원 탈퇴 시 데이터 정리
      프론트는 탈퇴 성공 후 기기 저장분을 지운다. 서버는 users 삭제 시 개인 데이터를 같이 지우고
      (CASCADE), withdrawal_logs 에는 번호와 시각만 남기며, 정지 기록은 유지한다.

15. 만드는 순서 (제안)
====================================================================
1단계  0번 바탕 작업 + 1번 인증 (signup, login, me, logout)  -> 프론트에서 바로 테스트 가능
2단계  2번 설정/동네 + 3번 일정 + 4번 월세/고정지출 + 5번 가계부  (홈과 마이페이지 핵심)
3단계  6번 알림 + 8번 메모 + 9번 고객센터
4단계  7번 커뮤니티 + 파일 업로드 + 신고
5단계  11번 관리자/이용 정지 + 10번 약관
6단계  1번의 휴대폰 인증, 소셜 로그인  (외부 서비스 연동)
7단계  12번 AI, 13번 지도/장소/날씨 서버화
