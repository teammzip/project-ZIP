# 회원·인증·약관 DB 검증

## 범위와 준비

대상 10개: users, social_accounts, auth_sessions, phone_verifications, password_resets, terms_documents, user_term_agreements, withdrawal_logs, user_settings, user_profiles. 실제 로그인·문자 인증·비밀번호 해싱·권한·법적 유효성 검증은 포함하지 않습니다. uploaded_files 및 사진 연결은 후속 파일 테스트 범위입니다.

최신 스키마가 적용된 **zip_test의 새 연결**에서 실행합니다. 진행 중인 다른 트랜잭션이 없어야 합니다. 기존 대출 테스트가 끝났다면 그 파일은 다시 실행할 필요 없습니다. 이번 파일은 스스로 가상 회원과 테스트 약관을 생성합니다. 실제 회원/기존 약관을 수정하지 않습니다. 동일 연결을 유지하고 실행 중 CREATE/ALTER/COMMIT/다른 START TRANSACTION은 실행하지 않습니다.

## 1. 정상 동작

03_auth_terms_positive.sql을 연결된 Workbench 편집기에서 열고 전체 실행합니다. A01~A13 모두 PASS가 예상 결과입니다. 중간 오류로 멈추면 이후 항목은 미검증이며, 같은 연결에서 ROLLBACK으로 정리하고 첫 오류를 확인하세요.

| ID | 검증한 내용 |
|---|---|
| A01 | 회원 기본 권한·상태, 소셜 회원의 NULL 로그인 정보 저장 |
| A02 | 소셜 계정과 회원 연결 |
| A03~A04 | 만료·폐기 시각을 조건으로 한 세션 조회 |
| A05~A06 | 인증 완료 값의 조건부 소비, 두 번째 UPDATE 0행 |
| A07~A08 | 재설정 토큰의 조건부 소비, 두 번째 UPDATE 0행 |
| A09 | 테스트 문서 3종의 버전·동의 시각 연결 |
| A10 | 회원별 설정 기본값과 프로필 연결 |
| A11 | 회원 삭제 시 연결 기록 CASCADE |
| A12 | 약관 원문·탈퇴 기록·회원 미연결 인증 기록 보존 |
| A13 | 최종 ROLLBACK으로 테스트 데이터 제거 |

조건부 소비는 이 SQL의 WHERE 규칙이 동작하는지 확인합니다. DB가 무조건 재사용을 막는다는 의미가 아니며, API도 동일한 원자적 조건 처리·목적/대상 검증·동시성 처리를 구현해야 합니다. 현재 코드는 실제 비밀번호 변경을 수행하지 않습니다.

전화번호 00000000000은 실제 연락 가능한 번호 대신 넣은 DB fixture입니다. 현재 DB는 번호 형식을 검증하지 않으므로 이 입력 성공을 서비스 전화번호 검증 통과로 기록하면 안 됩니다. SHA2는 가상 토큰 해시를 만드는 테스트용 표현이며 비밀번호/6자리 인증코드의 운영 저장 지침이 아닙니다. 테스트 회원은 실제 로그인 가능한 계정이 아닙니다.

## 2. 제약조건 오류

04_auth_terms_negative.sql은 **전체 실행하지 않습니다.**

1. B00의 USE부터 SAVEPOINT 다음 SELECT까지 한 번만 선택 실행합니다. member_id, other_id, terms_id가 모두 숫자이고 DB가 zip_test인지 확인합니다.
2. B01~B10을 문장 하나씩 선택 실행합니다. 각 주석의 오류 번호·키 이름이 일치해야 통과입니다. B01~B08·B10은 1062, B09는 1451입니다. 1048(NULL 변수), 1175(안전 업데이트), 테이블/문법 오류는 해당 검증 통과가 아닙니다.
3. 예상 밖 성공이면 FAIL로 기록하고 `ROLLBACK TO SAVEPOINT auth_negative_fixture;` 후 다음 검증을 진행합니다. 준비 상태를 잃었다면 최종 ROLLBACK 후 새로 시작합니다.
4. B99 정리 블록을 실행하고 PASS인지 확인합니다. 자동 증가 번호에 빈 값이 생기는 것은 정상입니다.

B09는 실제 약관이 아니라 이번 준비 블록에서 생성한 테스트 문서를 삭제하려 시도합니다. DELETE에는 숫자 기본키 조건을 사용합니다. 약관의 법적 적절성이 아닌 FK RESTRICT 동작만 확인합니다.

```text
최초 예상 밖 오류:
```

파일은 스키마에 정적으로 대조했지만 실제 MySQL 실행 결과는 아직 확인하지 않았습니다. 전체 스키마 검증을 완료한 것으로 기록하지 않습니다. 회원 전화번호 UNIQUE, 인증 완료 토큰 UNIQUE 등 이번 파일에 없는 추가 경계/제약조건은 별도 검증 대상입니다.
