# DB 파일 공개 전 보안 검토

## 이번 검토 결과

현재 작업 트리와 검토 시작 시점의 Git 스테이징 영역에 있는 db/ SQL·문서를 대상으로 확인했습니다. 실제 DB 서버에 접속하거나 운영 데이터를 조회한 검토는 아닙니다.

- schema.sql의 VALUES 데이터는 지역·주변 동네·가계부 분류·AI 주제·장소 분류·쓰레기 배출 예시·약관 원문입니다. 실제 회원·전화번호·이메일·주소·가계부 내역·문의·대화 데이터는 발견하지 못했습니다.
- seeds/event_defaults.sql은 공통 일정 카테고리와 항목 제목을 기존 회원에게 생성하는 INSERT SELECT입니다. 파일 안에 실제 회원 목록을 저장하지 않습니다.
- migrations/20261031_current_project.sql은 스키마 변경, 공통 데이터 추가, 기존 DB 내부의 할 일 이전·수입 분류 UPDATE입니다. 운영 행을 파일에 담은 덤프가 아닙니다.
- 컬럼 설명의 숫자로 된 전화번호 예시는 실제 회원 행이 아니지만 혼동을 피하도록 형식 설명으로 교체했습니다. 변경 전 예시는 스테이징 영역에 남아 있으므로 최종 커밋 전에 다시 스테이징해야 합니다.
- 비밀번호·토큰·HMAC는 컬럼 이름과 처리 설명으로 존재합니다. 실제 비밀번호·개인키·토큰·해시 값이나 인증정보가 포함된 접속 URL은 발견하지 못했습니다.
- 루트 .gitignore에 로컬 환경변수, 개인키, DB 백업·덤프·로컬 데이터 경로의 제외 규칙을 추가했습니다. 공개 가능한 .env.example 등에도 실제 비밀값을 넣으면 안 됩니다.

이 결과는 검토한 파일에 한정됩니다. 전체 Git 과거 이력, 원격 저장소, 다른 브랜치, 운영 DB, 백엔드 런타임 보안에 대한 무결성 보장은 아닙니다. SQL 설계 자체가 공개돼도 되는지는 저장소 공개 범위와 팀 정책을 확인해야 합니다.

## 커밋 전 확인

```powershell
git status --short
git diff --cached --stat
git diff --cached -- db .gitignore
```

현재 수정 사항이 이미 스테이징된 파일과 다를 수 있으므로, 검토한 최종 파일을 다시 git add한 뒤 확인합니다. 이 검토 작업은 자동 커밋·푸시하지 않습니다.

- 허용: 스키마, 마이그레이션 코드, 개인정보 없는 기본 데이터, 설계 문서.
- 금지: 실제 사용자 데이터, 운영 덤프, 비밀번호 해시, 토큰 해시, 차단 식별값 해시, 비밀키, 인증정보가 든 접속 문자열.
- 백업은 저장소 밖의 접근 제한된 위치에 보관합니다. db/backups/ 등은 실수 방지용 제외 경로일 뿐 안전한 백업 저장소가 아닙니다.
- .gitignore는 이미 추적·스테이징된 파일을 제외하지 않고 git add -f도 막지 못합니다. 파일명만으로 모든 민감 파일을 탐지할 수도 없습니다.
- 실제 비밀값이 커밋됐다면 먼저 폐기·교체하고, 공유된 Git 이력 정리는 팀과 협의합니다. 현재 파일에서 지우는 것만으로 이전 커밋에서 사라지지 않습니다.

## 백엔드에서 추가로 구현할 보안 요구사항

SQL에 외래키가 있다고 API 권한 검사가 구현된 것은 아닙니다. 현재 저장소의 DB 설계만으로 아래 기능의 구현 여부를 확인할 수 없습니다.

- 개인 데이터 조회·변경 시 인증된 사용자 ID로 소유권을 검사합니다. 카테고리·첨부 파일·메모 참조 대상도 같은 사용자 소유인지 검사합니다.
- 관리자 권한과 제재 상태를 서버에서 검사합니다. 요청 본문의 role, user_id를 권한 근거로 신뢰하지 않습니다.
- 비밀번호는 전용 비밀번호 해싱 방식으로 처리합니다. 6자리 문자 인증 코드는 단순 해시만으로 저장하지 말고 서버 비밀키 기반 검증값, 만료, 시도·발송 횟수 제한을 함께 설계합니다. 키는 저장소와 DB 밖에서 관리합니다.
- 재설정·휴대전화 인증 토큰은 목적·대상·만료·일회용 소비를 검증하고 동시 요청에서도 한 번만 사용되게 처리합니다.
- 사용자 입력은 바인딩된 파라미터로 처리하고, 업로드 파일의 크기·유형·소유권과 다운로드 권한을 검사합니다. 비공개 파일에 영구 공개 URL을 사용하지 않습니다.
- SQL의 집계 VIEW는 모든 회원의 데이터를 대상으로 합니다. API에서 user_id 조건을 적용하고 클라이언트에 DB 직접 접근 권한을 주지 않습니다. 런타임 DB 계정과 마이그레이션 계정을 분리하고 필요한 권한만 부여합니다.
- 탈퇴 후 남는 withdrawal_logs, banned_identities와 이전용 todos_legacy_20261031도 보호 대상입니다. 해시가 익명 데이터라는 가정으로 공개하지 않습니다. 보존 목적·기간과 정리 절차를 정하고, 할 일 이전 검증 후 보관 테이블 처리도 운영 절차에 포함합니다.
- 현재 약관에는 업체명·담당자 등 미완성 자리표시자가 있고, 탈퇴 후 차단 식별값 보관과의 설명 정합성을 확인해야 합니다. 출시 전 정책 담당자가 검토하고 필요한 변경은 새 약관 버전과 프론트 문구에 함께 반영합니다. 이번 작업에서는 기존 동의 원문과 React 파일을 변경하지 않았습니다.
