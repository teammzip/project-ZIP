ZIP - 외부 API 정리
====================================================================
작성일: 2026-11-01
목적: ZIP(자취생 생활 도우미)에 필요한 외부 API / 서비스를 한곳에 정리한다.
주의: 무료 한도, 승인 조건, 요금은 자주 바뀐다. 도입 전에 각 사이트에서 꼭 확인할 것.

공통 원칙
--------------------------------------------------------------------
1. 모든 API 키는 백엔드에만 둔다. 프론트에 넣으면 노출된다.
2. 같은 요청은 서버에서 캐시한다. (날씨 10분, 주소 검색 결과, 실거래가 하루 등)
   무료 한도를 아끼는 가장 쉬운 방법이다.
3. 공공데이터 API는 응답이 XML이거나 지자체마다 형식이 달라서
   프론트가 직접 부르지 말고, 백엔드가 받아서 정리해 내려준다.
4. 지금처럼 브라우저가 Nominatim, Open-Meteo를 직접 부르는 방식은
   사용자가 늘면 한도에 걸린다. 서버를 거치게 바꾼다.


1. 현재 사용 중인 외부 서비스 (프론트에서 직접 호출, 키 없음)
====================================================================
서비스            용도                          위치                               비고
----------------  ----------------------------  ---------------------------------  ----------------------------------
Open-Meteo        날씨(현재/시간별/일별 예보)   frontend/src/features/weather      무료, 키 없음, 해외 기상 모델 기반
Nominatim (OSM)   동네/주소 -> 좌표, 주소 검색  frontend/src/features/weather      초당 1회 제한, 한국 주소 정확도 낮음
Leaflet + OSM     지도 표시                     frontend/src/features/map          무료, 트래픽 커지면 타일 정책 주의

- 날씨는 실제 API를 실시간 호출한다(목업 아님). 페이지를 열 때 최신 예보를 받아온다.
- 날씨 데이터 자체보다 "동네 -> 좌표" 변환(Nominatim)이 더 약한 고리다.
- 지금 단계(시연/개발)에서는 그대로 둬도 괜찮다. 백엔드를 만들 때 함께 교체한다.


2. 공공데이터포털(data.go.kr)에서 가져올 만한 API  (모두 무료, 서비스키 발급)
====================================================================
용도                 API                                                    이 앱에서 쓰는 곳
-------------------  -----------------------------------------------------  --------------------------------------
날씨                기상청 단기예보 / 초단기실황                           Open-Meteo 대체 (한국 날씨 더 정확)
미세먼지             한국환경공단 에어코리아 대기오염정보                   홈 날씨 카드에 미세먼지 추가
쓰레기 배출 정보     지자체별 생활쓰레기 배출 정보(표준데이터)              쓰레기 배출 요일/시간 화면
약국                 건강보험심사평가원 약국 정보, 국립중앙의료원 약국     주변 약국, 영업 여부
병원/응급실          국립중앙의료원 응급의료기관 정보                       야간/응급 상황 안내
공휴일/기념일        한국천문연구원 특일 정보                               달력에 공휴일 자동 표시
상가/편의 시설       소상공인시장진흥공단 상가(상권) 정보                   주변 편의점, 세탁소, 식당
주민센터/민원        행정안전부 행정기관 정보                               동네 주민센터 위치와 전화번호
대중교통(선택)       국토부 버스도착정보, 서울 열린데이터 지하철 실시간    집 근처 교통 안내

- 기상청 API는 위경도를 격자 좌표(nx, ny)로 변환해서 호출해야 하고,
  응답이 T1H, PTY 같은 코드 형태라 변환 작업이 필요하다. 백엔드에서 처리 권장.
- 쓰레기 배출 정보는 지자체마다 형식이 달라서 서울/경기부터 붙이는 게 현실적이다.

3-1. 겹치는 기능은 왜 여러 개 적었나 (역할 구분)
====================================================================
같은 "주소/지도" 계열이라도 서비스마다 잘하는 일이 달라서 따로 적었다.
전부 쓰는 게 아니라, 아래 "최소 조합"만 고르면 된다.

[주소/위치 계열]
서비스                  잘하는 일                                 이 앱에서의 용도
----------------------  ----------------------------------------  ----------------------------------------
도로명주소 API(juso)    주소 "검색/자동완성" (공식 주소 DB)       설문, 가입 시 주소 입력. 입력창에 치면
                        - 좌표는 안 줌(주소 문자열만 정확하게)      후보 주소 목록을 보여주는 역할
VWorld / 카카오 로컬    주소 -> 좌표 변환 (지오코딩)              고른 주소를 위도/경도로 바꿔 지도 중심,
                                                                  날씨 조회 위치로 사용
카카오 로컬(키워드)     장소 검색 (약국, 편의점, 세탁방 등)       지도 화면의 주변 장소 표시
                        - 주소가 아니라 "가게/시설" 데이터
Nominatim(현재)         위 세 가지를 한꺼번에 어설프게 처리      지금은 이것 하나로 다 하고 있어서 한국
                                                                  주소 정확도가 낮음

  => 흐름: [주소 검색(juso)] -> 주소 선택 -> [좌표 변환(VWorld/카카오)] -> 지도/날씨에 사용
           지도에서 주변 시설을 보여줄 때만 [장소 검색(카카오 로컬)]을 추가로 사용

[지도 계열]
- Leaflet + OSM : 지도를 "그리는" 도구(현재 사용, 무료). 지도 화면 자체.
- 카카오맵 / VWorld 타일 : 같은 지도를 그리되 한국 지도가 더 정확하고 한도가 넉넉.
  트래픽이 커져 OSM 타일 정책에 걸릴 때만 교체. 처음부터 둘 다 쓸 필요 없음.

[날씨 계열]
- Open-Meteo : 현재 사용 중, 키 없음, 간단. 한국 동네 단위 정확도는 다소 낮음.
- 기상청 단기예보 : 한국 기준으로 더 정확. 대신 격자 변환/코드 해석이 필요.
- 에어코리아 : 날씨와 별개로 "미세먼지"만 제공. 기상청/Open-Meteo가 대신해주지 않음.
  => 둘 중 하나로 날씨를 쓰고, 미세먼지가 필요하면 에어코리아만 추가.

[인증/알림 계열]
- 휴대폰 인증(SMS) vs 이메일 : 둘 다 "본인 확인"용이라 겹침. 이메일은 무료,
  SMS는 유료. 둘 중 하나만 써도 되고, 이메일을 기본으로 하고 SMS는 선택.
- 푸시(FCM) : 앱 밖에서 알림을 보내는 용도. 이메일/SMS와는 목적이 다름.

[AI 계열]
- Gemini vs Claude : 같은 역할(AI 상담)의 대체재. 하나만 고르면 됨.
  무료로 시작하려면 Gemini, 품질이 중요해지면 Claude.

[최소 조합 추천 - 지금 계획 기준]
  주소 검색   : 도로명주소 API (juso)
  좌표 변환   : 카카오 로컬 또는 VWorld 중 하나
  장소 검색   : 카카오 로컬 (좌표 변환과 같은 키로 해결되므로 카카오로 통일하면 편함)
  지도 표시   : Leaflet + OSM 유지
  날씨        : Open-Meteo 유지 (나중에 기상청), 미세먼지는 에어코리아
  => 카카오 로컬 하나로 "좌표 변환 + 장소 검색"을 같이 처리하면 키 관리가 단순해진다.


4. 우선순위 (이 앱의 화면과 직접 연결되는 순서)
====================================================================
[필수 - 없으면 핵심 기능이 안 됨]
  1. 소셜 로그인 (카카오/네이버/구글)
  2. 도로명주소 API + VWorld (또는 카카오 로컬): 설문/동네 인증 주소 정확도
  3. 지도: Leaflet + OSM 유지 (트래픽이 커지면 카카오맵/VWorld 타일로 교체)
  4. 날씨: Open-Meteo 유지 (백엔드 생기면 기상청으로 교체)
  5. 휴대폰 인증: 개발 모드부터 (운영 때 유료 SMS 연결)

[강력 추천 - 서비스 품질/차별점]
  6. 쓰레기 배출 정보 (쓰레기 화면과 직접 연결)
  7. 기상청 단기예보 + 에어코리아 (한국 기준 날씨 강화)
  8. 공휴일(특일 정보) (달력에 공휴일 표시)
  9. AI 상담: Gemini 무료 티어로 시작, 품질이 중요해지면 Claude
 10. 이메일 발송 (비밀번호 재설정, 휴대폰 인증 보조)

[나중에]
 11. 푸시 알림 (FCM)
 12. 파일 저장 (R2)
 13. 오류 감시 (Sentry)
 14. 주변 장소 검색 (약국, 세탁방), 대중교통


5. 단계별 도입 순서 (제안)
====================================================================
1단계  백엔드(인증 서버) + 소셜 로그인 + 휴대폰 인증(개발 모드)
2단계  행안부 주소 API + 카카오 로컬/VWorld  -> 설문, 동네 인증 안정화
3단계  쓰레기 배출 공공데이터  -> 서비스만의 가치
4단계  기상청 + 에어코리아 (날씨 교체)  -> 백엔드 캐시 경유
5단계  AI 상담 (Gemini 무료 티어 -> 필요 시 Claude)
6단계  푸시 알림, 파일 저장, 오류 감시

참고
--------------------------------------------------------------------
- 날씨는 지금 그대로 둬도 괜찮다. 바꾸려면 백엔드(키 보관, 캐시)가 먼저 필요하다.
- 계정별 데이터 분리는 실제 서비스에서는 DB(SQL)가 필수다. db/schema.sql, db/seeds/ 참고.
- 프론트 API 명세는 frontend/API.md, DB 구조는 db/README.md 참고.


6. 있으면 좋지만 안 쓸 기능 (현재 계획에서 제외)
====================================================================
이 앱은 사용자가 월세/고정지출을 직접 입력하고 기록하는 용도라서,
아래 기능은 대응하는 화면과 DB가 없어 쓰지 않기로 했다.
나중에 해당 기능을 새로 만들 때만 다시 검토한다.

용도                 API                                                    비고
-------------------  -----------------------------------------------------  -----------------------------------
청년 지원 정책       복지로 중앙부처/지자체 복지서비스 (data.go.kr)         청년 월세 지원, 전세 대출 안내
전월세 실거래가      국토교통부 아파트/연립다세대/오피스텔 전월세 실거래가  내 월세와 동네 평균 비교용. 비교 기능이 없어 불필요
